# Архитектурные решения Garant.kg

Этот документ фиксирует ключевые технические решения, принятые в ходе разработки платформы.

## Общая архитектура

### API-First подход
**Решение**: Полностью API-driven архитектура на Django REST Framework без использования Django-шаблонов для UI.

**Обоснование**:
- Полное разделение frontend и backend
- Возможность создания мобильных приложений без изменения backend
- Независимое масштабирование компонентов
- Упрощённая интеграция с внешними сервисами

### Монорепозиторий
**Решение**: Единый репозиторий с директориями /backend, /frontend, /deploy, /docs.

**Обоснование**:
- Упрощённая синхронизация версий frontend и backend
- Единая система CI/CD
- Удобство для малой команды

## Backend

### Django 5 + DRF
**Решение**: Django 5 как основной фреймворк с Django REST Framework для API.

**Обоснование**:
- Зрелая экосистема с проверенными решениями
- Встроенная админ-панель
- ORM с поддержкой сложных запросов
- Большое сообщество и библиотеки

### PostgreSQL
**Решение**: PostgreSQL как основная СУБД.

**Обоснование**:
- Поддержка ACID транзакций (критично для финансовых операций)
- JSON поля для гибкости
- Полнотекстовый поиск
- Надёжность и производительность

### Argon2 для паролей
**Решение**: Argon2 как основной алгоритм хеширования паролей.

**Обоснование**:
- Победитель конкурса Password Hashing Competition
- Защита от GPU-атак
- Современный стандарт безопасности

### JWT для аутентификации
**Решение**: SimpleJWT с access token в памяти и refresh token в httpOnly cookie.

**Обоснование**:
- Stateless аутентификация
- Безопасность (httpOnly защищает от XSS)
- Короткий lifetime access token (15 мин)
- Blacklist для отзыва токенов

### Celery для фоновых задач
**Решение**: Celery + Redis для асинхронных задач и периодических заданий.

**Обоснование**:
- Отправка email уведомлений
- Автопринятие этапов сделок
- Обработка платежей
- Генерация отчётов

## Структура приложений

### Модульная архитектура
**Решение**: Разделение на 13 Django-приложений по доменам: accounts, profiles, categories, marketplace, deals, payments, messaging, files, disputes, reviews, notifications, moderation, audit.

**Обоснование**:
- Separation of Concerns
- Упрощение тестирования
- Возможность независимого развития модулей
- Ясная структура кода

### Слои в приложениях
**Решение**: Чёткое разделение на models, serializers, services, selectors, views, permissions, filters.

**Обоснование**:
- Бизнес-логика изолирована в services (не в views)
- Views остаются тонкими
- Упрощение тестирования
- Переиспользование кода

## Бизнес-логика

### Конечный автомат для сделок
**Решение**: Явный конечный автомат (FSM) для статусов сделки с валидацией переходов в сервисном слое.

**Обоснование**:
- Гарантия корректности переходов
- Отсутствие неопределённых состояний
- Аудит всех изменений статуса
- Предсказуемое поведение

### Ledger с двойной записью
**Решение**: Внутренний ledger для учёта всех финансовых операций с принципом двойной записи.

**Обоснование**:
- Полная прозрачность движения средств
- Защита от ошибок в расчётах
- Аудит всех транзакций
- Возможность сверки балансов

### Абстракция платёжного провайдера
**Решение**: Интерфейс PaymentProvider с реализацией FakePaymentProvider для разработки.

**Обоснование**:
- Независимость от конкретного платёжного партнёра
- Возможность тестирования без реальных платежей
- Простая замена провайдера в будущем

### Идемпотентность операций
**Решение**: Поддержка Idempotency-Key для критичных операций (платежи, изменение статусов).

**Обоснование**:
- Защита от дублирования операций при повторных запросах
- Безопасность при network errors
- Соответствие best practices финтех-приложений

## Frontend

### React + TypeScript + Vite
**Решение**: React 18 с TypeScript и Vite как сборщик.

**Обоснование**:
- Быстрая разработка (Vite HMR)
- Типобезопасность (TypeScript)
- Большая экосистема компонентов
- Хорошая производительность

### TanStack Query
**Решение**: TanStack Query (React Query) для управления серверным состоянием.

**Обоснование**:
- Автоматическое кэширование
- Инвалидация и рефетч
- Оптимистичные обновления
- Упрощение работы с API

### Tailwind CSS
**Решение**: Tailwind CSS для стилизации.

**Обоснование**:
- Быстрая разработка UI
- Консистентный дизайн
- Mobile-first подход
- Малый размер финальной сборки

## Безопасность

### Защита от IDOR
**Решение**: Объектные permissions на уровне DRF для каждого эндпоинта.

**Обоснование**:
- Пользователь видит только свои данные
- Проверка прав на уровне объекта
- Защита от несанкционированного доступа

### Rate Limiting
**Решение**: DRF throttling с разными лимитами для анонимов и авторизованных.

**Обоснование**:
- Защита от DoS
- Защита от брутфорса
- Контроль нагрузки на API

### Django Axes
**Решение**: django-axes для защиты от брутфорса логина.

**Обоснование**:
- Автоматическая блокировка после N неудачных попыток
- Блокировка по IP + username
- Настраиваемый cooloff период

### Audit Log
**Решение**: Неизменяемый журнал всех значимых действий пользователей.

**Обоснование**:
- Полная история для разбора споров
- Соответствие требованиям безопасности
- Защита от fraud

## Инфраструктура

### Docker Compose
**Решение**: Docker Compose для dev и prod окружений.

**Обоснование**:
- Воспроизводимость окружений
- Упрощение онбординга разработчиков
- Изоляция сервисов
- Лёгкое развёртывание

### Nginx как reverse proxy
**Решение**: Nginx для проксирования запросов к backend и отдачи статики frontend.

**Обоснование**:
- Высокая производительность
- SSL termination
- Gzip сжатие
- Кэширование статики

### GitHub Actions для CI/CD
**Решение**: GitHub Actions для автоматизации тестирования и развёртывания.

**Обоснование**:
- Интеграция с GitHub
- Бесплатные минуты для открытых проектов
- Гибкие workflows
- Поддержка матричного тестирования

## Тестирование

### Pytest для backend
**Решение**: pytest + pytest-django для тестирования backend.

**Обоснование**:
- Мощные fixtures
- Параметризация тестов
- Plugins для Django
- Читаемые assertion errors

### Vitest для frontend
**Решение**: Vitest для unit-тестов frontend.

**Обоснование**:
- Совместимость с Vite
- Jest-compatible API
- Быстрое выполнение
- Поддержка TypeScript

### Playwright для E2E
**Решение**: Playwright для end-to-end тестов.

**Обоснование**:
- Кроссбраузерность
- Автоожидание элементов
- Параллельное выполнение
- Debugging tools

## Что НЕ включено в MVP

### Реальные платежи
**Решение**: Заглушка вместо реального платёжного провайдера.

**Обоснование**:
- Требуется юридическое оформление
- Нужно выбрать провайдера (в КР: ЭЛСОМ, Мбанк, O!Деньги)
- Архитектура готова к интеграции

### 2FA
**Решение**: Структура готова, но не обязательно для MVP.

**Обоснование**:
- Усложняет UX
- Можно добавить опционально позже

### WebSocket для чата
**Решение**: REST API + polling для MVP, готовность к WebSocket.

**Обоснование**:
- Проще реализация
- Достаточно для MVP
- Django Channels можно добавить позже
